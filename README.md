## About

I'm a **Bulgarian student developer** working at the intersection of **software engineering, artificial intelligence, and embedded systems**. I enjoy building complete products: from an ESP32 sensor node and its communication protocol to the backend, database, desktop interface, and AI layer that turn raw data into something useful.

My projects often start with a concrete problem in **healthcare assistance, accessibility, agriculture, environmental monitoring, or home automation**. I focus on working prototypes, clear system boundaries, practical deployment, and learning through hands-on engineering.

I'm also **CEO & Co-Founder of [Bolyar Coders](https://github.com/BolyarCoders)**, where I collaborate on software and technology projects.

### What I'm focused on

- **Applied AI & voice interfaces** — LLM tool use, model routing, speech recognition, Bulgarian-language assistants, computer vision, and intelligent automation.
- **Embedded & wireless systems** — ESP32, sensors, custom PCB prototypes, ESP-NOW, Wi-Fi, BLE, and communication between physical devices and applications.
- **End-to-end software** — desktop applications, REST APIs, web interfaces, databases, and containerized services.
- **Real-world reliability** — hardware debugging, integration testing, observable failures, explicit APIs, and keeping critical decisions outside probabilistic model output.
- **Technology with a purpose** — assistive tools, remote care, agricultural monitoring, and accessible interfaces.

## How I Build

```text
Start with a real problem.
Build and test the hardware.
Define clear interfaces between components.
Use AI where it adds value — not where it replaces certainty.
Measure, debug, iterate, and ship something usable.
```

Some principles I try to follow:

- **Build the whole system** — firmware, communication, services, data, and UI should work together, not just in isolated demos.
- **Keep control explicit** — an AI assistant can suggest or explain, but hardware commands and safety-related actions need clear, testable rules.
- **Prefer useful prototypes** — validate assumptions with actual sensors, real network conditions, and user interactions.
- **Make problems visible** — diagnostics, logging, repeatable tests, and honest error reporting are part of engineering.
- **Design to evolve** — separate components so sensors, models, backends, and interfaces can change independently.
